System overview

Three places do work. The browser does as much as it can, because that costs nothing and keeps files private. Vercel serves pages and a thin API. A worker container takes the jobs a browser can't do well. It only makes outbound connections, so it can run on your current machine with no open ports.

Browser

Renders the UI and runs 30 tools with WebAssembly and Canvas inside a Web Worker. Nothing is uploaded for these tools.

Vercel

Pre-rendered tool pages for SEO, plus short API calls: create job, sign upload URLs, report status, authenticate API keys.

Worker

Pulls jobs from Redis, reads inputs from R2, runs native tools in a locked-down container, writes results back, and deletes expired files.

Vercel isn't used for the heavy processing. Its Functions have a 4.5 MB request body limit, 1 vCPU on Hobby, and 4 CPU-hours a month included, and the Hobby plan is for non-commercial use only.

How a job runs

Browser tool (for example, Merge PDF)

The page lazy-loads the tool's engine into a Web Worker. Files are read with the File API, processed in memory, and saved with a Blob download. The only network traffic is loading the page and the engine code. Server tools and browser tools share the same upload component, so switching a tool between the two is a registry change, not a redesign.

Server tool (for example, Compress PDF)

sequenceDiagram
  participant B as Browser
  participant V as Vercel API
  participant R as Upstash Redis
  participant S as Cloudflare R2
  participant W as Worker
  B->>V: POST /api/jobs (tool, file sizes, Turnstile token)
  V->>R: check rate limit, create job record (expires in 1 h)
  V-->>B: job id + signed upload URLs (10 min)
  B->>S: PUT each file (max 25 MB)
  B->>V: POST /api/jobs/{id}/start
  V->>R: push job id onto queue
  W->>R: BLMOVE job to processing list
  W->>S: download inputs
  W->>W: run tool with time and memory limits
  W->>S: upload result
  W->>R: status done, result key
  B->>V: GET /api/jobs/{id} (poll every 1.5 s)
  V-->>B: signed download URL (10 min)
  Note over W,S: Sweeper deletes files older than 1 h every 5 min

Polling is deliberate. At this traffic it costs a handful of function calls per job, and it avoids long-lived connections that serverless functions handle poorly. BLMOVE to a processing list means a worker crash doesn't lose jobs: on startup the worker re-queues anything left there.

Components

Web app on Vercel

  • Next.js App Router, TypeScript. Tool pages are statically generated from the tool registry, so adding a tool adds its Arabic and English pages, sitemap entries and API endpoint in one place.
  • i18n with next-intl. Arabic at /merge-pdf, English at /en/merge-pdf. <html dir> follows the locale.
  • Tailwind CSS with logical properties only (ms-*, pe-*, start-*), so every component mirrors for RTL without separate styles.
  • Route handlers for /api/jobs/* and the developer API under /v1/* (served at api.[yourdomain] through a rewrite).

In-browser engine

  • PDF: pdf-lib (merge, split, rotate, crop, watermark, page numbers, sign), pdf.js (thumbnails, PDF to JPG, compare), qpdf compiled to WebAssembly (AES-256 protect and unlock).
  • Arabic text in PDFs: harfbuzzjs shapes text before pdf-lib draws it. pdf-lib alone does no shaping or bidi, so Arabic would come out as disconnected, reversed letters.
  • Images: jSquash codecs (MozJPEG, OxiPNG, WebP, AVIF) for compression, pica for high-quality resizing, libheif-js for HEIC input, Konva for the photo editor and meme generator. Canvas text shapes Arabic natively.
  • Face blur: MediaPipe Face Detector (WASM), then a canvas blur.
  • Each engine is code-split per tool and runs in a Web Worker via Comlink, so the page stays responsive and ad scripts never touch file bytes on the main thread.

File storage and the 1-hour rule

  • Cloudflare R2 bucket, no public access. Uploads and downloads use signed URLs that expire in 10 minutes. The signature covers Content-Length, and the worker checks size and file type (magic bytes) again.
  • Keys are grouped by hour, jobs/2026-09-12T19/{jobId}/…, so the sweeper deletes whole hour prefixes instead of listing every object.
  • R2 lifecycle rules work in days, not hours. The worker's sweeper enforces the 1-hour promise; a 1-day lifecycle rule is only a backstop if the worker is down.
  • Result downloads set Content-Disposition with an RFC 5987 filename* so Arabic filenames survive.
  • "Delete now" on the result page removes the job's prefix immediately.

Queue and databases

  • Upstash Redis: job queue (lists with BLMOVE), job state as hashes that expire after 1 hour, and per-IP rate limits via @upstash/ratelimit. Because job state expires, visitor job records vanish on the same schedule as their files.
  • Neon Postgres: only for data that must last: developer accounts, hashed API keys, a usage ledger, credit balances, and payment webhook events. Drizzle ORM, with migrations kept in the repo.
  • Visitor jobs never touch Postgres, so it can scale to zero between API requests.

Worker

  • One Docker image: Node.js 22 job runner, plus LibreOffice, Ghostscript, qpdf, OCRmyPDF, Playwright Chromium, and a Python environment for pdf2docx, pdfplumber, PaddleOCR, rembg and ONNX Runtime. The self-hosted models are fallbacks behind the AI gateway.
  • Two job lanes on 4 cores: a light lane (2 at a time: compress, conversions, protect, AI API calls) and a heavy lane (1 at a time: self-hosted OCR and background removal when the free APIs are exhausted), so a slow CPU model never blocks a quick conversion.
  • Each job runs in its own temp directory as a non-root user, with a hard timeout and memory cap. LibreOffice gets a fresh profile per job with macros disabled; Ghostscript runs with -dSAFER.
  • No inbound ports. It only needs outbound HTTPS to R2 and TLS to Upstash, which is why it can run on your current machine behind a home router.
  • The developer API needs every tool on the server, including the 30 browser tools. packages/pdf-core and packages/image-core run in Node too, so the worker reuses the same code.

AI gateway

AI tools call free API tiers first and fall back to open-source models on the worker. The gateway lives in packages/ai-gateway and runs only on the worker. Provider keys are entered in the admin dashboard (below) and only the worker can decrypt them.

  • Adapters by capability. Each provider adapter declares what it can do: ocr.ar, translate, summarize, background.remove. Adding a provider is one adapter in code, then its key in the dashboard.
  • Quota tracking. Usage counters per provider per minute, day and month in Redis. The gateway also reads the rate-limit headers each response returns, because several providers only show limits in their dashboards and change them without notice.
  • Failover. A 429 or 5xx puts that provider on a cooldown. The next provider in the order is tried; when all are exhausted, the job goes to the self-hosted model or waits in the queue with a clear message.
  • One account per provider. Opening several accounts with one provider to stack free quota breaks OpenRouter's terms outright and likely Google's, Groq's and Cerebras's. Load is balanced across different providers only.
  • Long documents. Summaries are built chunk by chunk (summarize each section, then summarize the summaries), sized to each provider's token limits. Groq's free tier allows 8K tokens a minute, so long PDFs go to a provider with a larger allowance.

AI routing rules

  • Gemini is for visitors outside Europe only. The job API records the visitor's country from Vercel's x-vercel-ip-country header. Visitors from the EU, Iceland, Liechtenstein, Norway, the UK and Switzerland never go to Gemini's free tier; a missing country counts as Europe.
  • Gemini goes last in every order, so it only takes overflow.
  • OCR and PDF to Word never use Gemini's free tier, because scans of IDs, contracts and invoices tend to go through them. Only Summarize and Translate may.
  • Developer API jobs never use free tiers. They go to paid providers, paid for by the customer's credits.
  • Disclosure. AI tool pages show one line naming the provider type before a file is sent, for example "Processed by Google Gemini; Google may review content to improve its services", and the privacy policy lists every AI provider.

Admin dashboard

A private area at /admin where the owner manages AI providers without editing server files or redeploying.

  • Sign-in: one allow-listed owner account with a passkey, plus an authenticator app as backup. Every other visitor gets a 404. Admin routes are rate-limited and protected by Turnstile.
  • Provider cards: each provider has a card showing:
    • the fields it needs (key, endpoint, region or account ID)
    • an on/off switch
    • status: working, cooling down, out of quota, or key rejected
    • usage today and this month against its free limit
    • a Test button that runs a tiny request through the worker
  • Routing controls: drag to reorder providers per capability, a "stop at % of free limit" safety margin, and the "allow visitors from Europe" flag, which is locked off for Gemini's free tier.
  • Keys can be written, never read back:
    • The browser encrypts each key with the worker's public key (libsodium sealed box) before it is sent.
    • Postgres stores only that ciphertext, and only the worker holds the private key. Vercel, the database and the dashboard cannot decrypt stored keys.
    • The dashboard shows the last four characters. Replacing a key overwrites it.
  • Propagation: after a save, the worker picks up the change through a Redis notification within seconds, with no restart.
  • Audit log: every change is recorded with time and IP.

Developer API and billing

  • REST under /v1, asynchronous like the website: create job, upload, start, poll or receive a webhook, download.
  • API keys look like ak_live_…. Only a SHA-256 hash and a short prefix are stored.
  • Prepaid credits rather than monthly invoices: developers buy credit packs through Stripe Checkout (or Paddle), and each tool costs a set number of credits in the registry. No surprise bills and simpler failure handling.
  • An OpenAPI 3.1 spec generated from the same Zod schemas the handlers validate against, rendered as bilingual docs with Scalar.
  • API jobs get their own queue priority, so paying traffic isn't stuck behind free visitors.

Ads and consent

  • Google AdSense in fixed, reserved slots (no layout shift): a leaderboard on catalog pages, a sidebar on tool and result pages. No ads between the upload and the download button.
  • Ad scripts load after the tool UI is interactive. Visitors from the EEA, UK and Switzerland need a Google-certified consent banner; Google's own Privacy & messaging tool covers this.

Arabic and bilingual details

Text shaping

Anything that writes Arabic into a PDF (page numbers, watermarks, signatures, Hijri stamps, edits) goes through one function in packages/arabic: bidi reordering, then HarfBuzz shaping with the chosen font, then glyph drawing with pdf-lib. Tests cover lam-alef ligatures, diacritics, mixed Arabic and Latin runs, and numbers inside Arabic sentences.

Arabic text fix

Many PDFs store Arabic as visual-order presentation forms (U+FB50–U+FEFF). Extracted as-is, the text comes out reversed and letter by letter. The fixer maps presentation forms back to base letters (NFKC), rebuilds logical order per line with the Unicode bidi algorithm, and repairs spacing between words. It runs automatically inside PDF to Word and is also offered as a standalone tool.

Arabic OCR

Before building P4, run a benchmark on 30 or more real scans (printed books, government forms, phone photos, mixed Arabic and English), measuring character error rate and seconds per page on this machine. Candidates: Azure Document Intelligence, Google Cloud Vision and OCR.space through the gateway, plus PaddleOCR PP-OCRv5 Arabic and Tesseract ara self-hosted. The results set the gateway's OCR order and confirm the fallback is good enough. Surya's model weights are only free below $5M revenue or funding, so it is left out.

Dates, digits and fonts

  • Hijri dates use the browser's Umm al-Qura calendar (ar-SA-u-ca-islamic-umalqura), with a note that official dates can differ by a day.
  • Digits are a setting on every numbering tool: Arabic-Indic (١٢٣) or Western (123). The site UI default is still an open decision.
  • Bundled fonts are all OFL-licensed: Amiri and Noto Naskh Arabic (Naskh), Reem Kufi and Noto Kufi Arabic (Kufi), and Aref Ruqaa (Ruqaa). Good free Thuluth fonts are rare, so Thuluth is not offered at launch.

SEO

  • Latin slugs in both languages (/merge-pdf, /en/merge-pdf). Arabic slugs percent-encode into long, unreadable links when shared.
  • hreflang pairs for ar and en, with Arabic as x-default. Each page has Arabic-first copy, step-by-step instructions, an FAQ, and SoftwareApplication structured data.
  • Sitemaps and Open Graph images are generated from the registry. Check that the OG image renderer shapes Arabic correctly; if not, pre-render the images at build time.

Security and abuse

  • Server-side request forgery. HTML to PDF and HTML to image make the worker fetch any URL, and the worker sits on your home network. Chromium runs in a separate container whose only way out is a proxy that blocks private, loopback and link-local addresses, including after redirects and DNS changes.
  • Hostile files. Magic-byte checks, page and pixel caps (to stop decompression bombs), per-job timeouts and memory limits, LibreOffice macros off, Ghostscript -dSAFER, and no network access for the processing containers.
  • Free-tier abuse. Cloudflare Turnstile (invisible) on server jobs, per-IP limits in Redis (for example, 20 server jobs an hour), and a visible queue position when the heavy lane is busy.
  • Secrets. R2 and Redis credentials are scoped: Vercel can only sign URLs and write queue entries; the worker has a separate R2 token. AI provider keys are sealed to the worker's public key, so a leaked database or Vercel environment doesn't expose them. Developer API keys are hashed; webhooks are signature-verified.
  • Privacy wording. "Never uploaded" is only claimed on browser tools, and the page badge comes from the registry, so the claim can't drift from the code.

Roadmap

Phases run in order because each depends on the last. The public launch comes after P7, with every tool live. P0–P2 can go live earlier as a private beta on Vercel Hobby, since it's non-commercial while there are no ads.

  1. Foundation

    Monorepo, tool registry, design tokens from the mockup, bilingual RTL layout, shared upload component, tool page template with SEO, analytics, CI, and a Playwright test that renders every tool page in both languages.

    Done when: the home page and 47 placeholder tool pages build in Arabic and English with valid hreflang and sitemaps.

  2. Browser PDF tools

    The 17 browser PDF tools, plus the Hijri stamp and Arabic fonts. Builds packages/arabic shaping first, because six of these tools write Arabic text.

    Done when: each tool passes fixture tests (encrypted, scanned, very large and right-to-left PDFs) in Chrome, Safari and Firefox, including iOS Safari memory limits.

  3. Browser image tools

    The 9 image tools and face blur, with HEIC input and batch processing.

    Done when: a 25 MB photo batch processes on a mid-range Android phone without crashing the tab.

  4. Server pipeline

    R2, Upstash queue, job API, worker image, sweeper, egress proxy, Turnstile and rate limits. Then Compress, Repair, Office to PDF, HTML to PDF and image, PDF/A, and Redact.

    Done when: files are provably gone after 60 minutes, killing the worker mid-job loses nothing, and the SSRF tests fail to reach the LAN.

  5. AI gateway, Arabic OCR and PDF to Office

    Admin dashboard for provider keys, then the AI gateway with quota tracking, failover and routing rules. OCR benchmark and provider order, then OCR PDF, PDF to Word, PowerPoint and Excel, and the Arabic text fix.

    Done when: the chosen engine meets an agreed character error rate on the benchmark set, and Arabic PDF to Word output reads correctly in Word.

  6. AI tools

    Remove background, Summarize PDF and Translate PDF through the gateway, with provider disclosure lines; Upscale in the browser.

    Done when: each tool keeps working with any single provider switched off, and Europe-located test requests never reach Gemini.

  7. Developer API and billing

    Developer sign-up, API keys, credits, Stripe or Paddle checkout and webhooks, OpenAPI docs in both languages, server versions of the browser tools.

    Done when: an outside developer can buy credits and call three tools using only the docs.

  8. Ads, legal and launch hardening

    AdSense, consent banner, privacy policy and terms in both languages, load test at 10× expected traffic, error monitoring, choose hosting option A or B, go public.

    Done when: Lighthouse performance stays above 90 on tool pages with ads loaded.

After launch: Google Drive or Dropbox import if visitors ask for it.
